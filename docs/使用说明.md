# 使用说明

> 面向部署与日常使用。构建、协议和算法细节见
> [`README.md`](../README.md) 与
> [`技术方案_通达信缠论自动标注系统.md`](./技术方案_通达信缠论自动标注系统.md)。

## 1. 适用范围与前置条件

- 通达信为 **Windows x64** 版本；本项目 DLL 为 x64，32 位通达信无法加载。
- 部署前先退出通达信，避免 DLL 被占用导致拷贝失败。
- 首次使用需要完成 DLL 部署、DLL 绑定、通达信系统设置和公式导入。

## 2. 首次部署

### 2.1 部署文件

在仓库根目录执行：

```powershell
.\deploy_to_tdx.bat <通达信安装目录>
```

参数改为目标机的通达信安装目录。脚本会构建并拷贝以下文件到
`<通达信安装目录>/T0002/dlls/`：

- `tdx_czsc_bridge.dll`
- `tdx_czsc_service.exe`
- `libprotobuf.dll`
- `abseil_dll.dll`

不要只拷贝 `tdx_czsc_bridge.dll`；缺少运行库或服务程序会导致 DLL 加载失败或
分析请求一直降级为 0。

### 2.2 绑定 DLL 编号

检查 `<通达信安装目录>/T0002/dlls/dlls.ini`，确认 DLL 已绑定到公式使用的编号：

```ini
band1 = tdx_czsc_bridge.dll
```

公式模板固定使用 `TDXDLL1`，因此对应 `band1`。如果目标机使用其他编号，需要
同时修改公式中的 `TDXDLL1`。

### 2.3 关键系统设置（换机必做）

打开通达信：

1. 按 `Ctrl+D` 打开“系统设置”（或 `工具/选项 → 系统设置`）。
2. 进入 `设置3`。
3. 勾选 **“主图指标不影响坐标的高低值”**。
4. 点击“确定”，然后切换周期或重新打开主图。

**为什么必须勾选**：本项目的主图叠加公式在无信号 K 线上会输出 `0`（例如
`301/302` 中枢通道在区间外为 0，`STICKLINE` 等绘图函数会使用这些值）。未勾选
该选项时，通达信会自动把 0 计入主图坐标的最低值，导致 Y 轴从 0 开始，K 线
整体上移并被压缩到上方一条窄带内。现象出现在新电脑上，通常不是 DLL 或 Rust
服务计算错误，而是该通达信本机设置没有随部署包一起带过去。

### 2.4 导入公式

按公式类型分别导入 `tdx_formula_examples/` 下的模板：

| 文件 | 公式类型 | 属性/用途 |
|---|---|---|
| `main_chart_full.tn6` | 技术指标 | **主图叠加**：分型、笔、段、中枢 |
| `buy_sell_expert.tn6` | 交易系统（专家系统） | 生成 B/S 买卖指示，可回测 |
| `buy_sell_mark.tn6` | 技术指标 | **主图叠加**：买卖点类型文字/图标 |
| `atr_tp_sl.tn6` | 技术指标 | **主图叠加**：买点 ATR 止盈止损线 |
| `chan_select.tn6` | 条件选股 | 30 分钟周期选股 |

注意事项：

- 专家系统公式不允许使用 `DRAWTEXT`/`DRAWICON`/`STICKLINE` 等绘图函数，否则会报
  `TDXSTEPxx 不是指定的输出名`；类型文字请用 `buy_sell_mark.tn6` 叠加。
- 公式中 950 量能通道建议放在 401~406 之前，仓库模板已按此顺序编写。
- 首次加载主图约需 1~2 秒，DLL 会自动拉起 Rust 服务；后续滚动/缩放走缓存。

## 3. 日常使用

- 主图加载 `main_chart_full` 后，分型、笔、段、中枢会随 K 线滚动和周期切换自动刷新。
- 买卖点箭头用 `buy_sell_expert`；需要“一买/二买/三买”等文字时再叠加
  `buy_sell_mark`。
- ATR 止盈止损线用 `atr_tp_sl`，按模板顶部参数调整 ATR 周期、止损/止盈倍数和
  触发方式。
- 选股用 `chan_select`，在选股器中把周期设为 **30 分钟**。
- Rust 服务由 DLL 自动启动和回收，日常不需要手动运行 `tdx_czsc_service.exe`。

## 4. 日志与诊断

| 内容 | 位置 |
|---|---|
| DLL 日志 | `<通达信安装目录>/T0002/dlls/logs/tdx_czsc_bridge.log` |
| 服务日志 | `<通达信安装目录>/T0002/dlls/tdx_czsc_service.log` |
| 调试通道 | 取消 `main_chart_full.tn6` 中 902/903 的注释 |

排查无显示问题时，先看 DLL 日志是否收到请求，再看服务日志是否有分析失败。

## 5. 常见问题

### 5.1 K 线整体上移、可视部分被压得很窄

优先检查 2.3 的 **“主图指标不影响坐标的高低值”** 是否已勾选。这是换机后最常见
的显示差异；勾选后无需修改 DLL 或 Rust 服务。

如果已勾选仍异常，再检查主图坐标是否被设为“百分比/对数”等模式，以及
`main_chart_full` 的公式属性是否确为“主图叠加”。

### 5.2 主图完全没有缠论标注

按顺序检查：

1. 通达信是否为 x64 版本；
2. `dlls.ini` 的 `band1` 是否指向 `tdx_czsc_bridge.dll`，修改后是否重启通达信；
3. `T0002/dlls/` 下是否同时存在服务程序和运行库；
4. `tdx_czsc_bridge.log` 是否出现 `BuildRequest`，`tdx_czsc_service.log` 是否报错。

### 5.3 专家系统公式报 `TDXSTEPxx` 错误

说明绘图函数放进了交易系统公式。把买卖点类型标注移到
`buy_sell_mark.tn6`（技术指标/主图叠加），专家系统公式只保留
`ENTERLONG`/`EXITLONG`。

### 5.4 部署脚本提示 `copy failed`

通常是通达信未完全退出，DLL 仍被占用。关闭所有通达信窗口（包括托盘进程）后
重新执行部署脚本。

## 6. 换机/升级检查清单

- [ ] 目标机为 Windows x64 通达信；
- [ ] 已退出通达信并完成部署脚本拷贝；
- [ ] `dlls.ini` 的 `band1` 已绑定；
- [ ] 已勾选“主图指标不影响坐标的高低值”；
- [ ] 已重新导入公式并设置正确的公式类型/主图叠加属性；
- [ ] 主图能看到分型、笔、段、中枢，K 线高度正常；
- [ ] DLL 与服务日志无异常。
